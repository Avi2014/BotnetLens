# Data Directory

Large dataset files are **not stored in Git** (GitHub's 100 MB per-file limit). This README tells you exactly how to get the data, where to put it, and how to regenerate all derived files from scratch.

---

## Directory layout

```
data/
├── raw/            ← original CTU-13 binetflow files (you download these)
├── interim/        ← merged raw CSV + per-family pools (generated by pipeline)
├── processed/      ← feature-engineered flow dataset (generated by pipeline)
└── splits/         ← train / val / test / holdout CSVs (generated by pipeline)
```

`.gitkeep` files hold the empty folders in Git so the pipeline never crashes on a missing directory.

---

## Step 1 — Download CTU-13

The CTU-13 dataset is publicly available from the Czech Technical University:

| Resource | URL |
|---|---|
| Dataset page | https://www.stratosphereips.org/datasets-ctu13 |
| Direct download (all scenarios, ~8 GB) | https://mcfp.felk.cvut.cz/publicDatasets/CTU-13-Dataset/CTU-13-Dataset.tar.bz2 |

```powershell
# Windows — download with curl (Git Bash / WSL also work)
curl -L -o data/raw/CTU-13-Dataset.tar.bz2 `
  "https://mcfp.felk.cvut.cz/publicDatasets/CTU-13-Dataset/CTU-13-Dataset.tar.bz2"

# Extract (requires 7-Zip or tar ≥ 1.17)
tar -xjf data/raw/CTU-13-Dataset.tar.bz2 -C data/raw/
```

> **Note**: The dataset covers 2011 traffic with botnet families Neris, Rbot, Virut, Menti, Sogou, Murlo, and NSIS.ay. It is **not** a Mirai-labelled dataset. Keep the original scenario sub-folders intact (e.g. `CTU-13-Dataset/1/`, `CTU-13-Dataset/2/`, …).

## Step 2 — Regenerate all derived files

With the virtual environment active:

```powershell
# 1. Activate venv
.venv\Scripts\Activate.ps1

# 2. Run the full pipeline (extract → clean → feature-engineer → split)
python src/run_full_pipeline.py
```

This produces, in order:

| Script | Output |
|---|---|
| `src/extract_ctu13.py` | `data/interim/ctu13_raw.csv` (~3.9 GB) |
| `src/feature_engineering.py` | `data/processed/ctu13_flows.csv` (~4 GB) |
| `src/split_data.py` | `data/splits/train.csv`, `val.csv`, `test.csv`, `holdout.csv` |
| `src/preprocessing.py` | label mapping, cleaning log under `reports/dataset/` |

Approximate runtimes on a mid-range laptop:

| Stage | Time |
|---|---|
| Extract + merge | ~5 min |
| Feature engineering | ~15 min |
| Splitting | ~3 min |

| `reports/cascade_sample_output.csv` | Sample cascade output with explanation column |
| `reports/dataset/data_quality_summary.csv` | Row/null/class counts after cleaning |

Pull these with a plain `git pull` — no large-file tooling needed.

## Troubleshooting

**Pipeline fails on missing file**: Check that `data/raw/` contains the extracted CTU-13 scenario folders. The extractor looks for `*.binetflow` files recursively.

**Label issues**: See `reports/dataset/label_mapping.csv` for the full raw-label → binary/family mapping. Unresolved labels are preserved as-is; the code does not guess.

**Different results than the paper**: Make sure you use the same `config/default.yaml` (random seed, split ratios). Re-running feature engineering on a different OS may produce minor floating-point differences in some features.
